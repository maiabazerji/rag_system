# Corpus de démonstration : documents d'entreprise en français

**All data in this folder is synthetic and fictional.** Every company, address,
SIREN/SIRET, VAT number, IBAN, phone number, e-mail address, contract, invoice and
certificate was invented for testing EvalRAG. No document comes from a real
organisation, and none contains personal data: signatories are named only by role
("Président", "Gérante"). Any resemblance to an existing company is coincidental.

**Toutes les données de ce dossier sont synthétiques et fictives.** Aucune donnée
personnelle. Les documents ne sont pas représentatifs de toutes les entreprises
françaises, et leur contenu juridique ou fiscal ne constitue pas un conseil ni un modèle
à réutiliser tel quel.

## Purpose

The bundled corpus in `data/docs/` is English prose about RAG. This corpus tests a
different case: short, number-heavy French business documents that refer to one
another, where answers depend on exact amounts, dates and contract clauses. It
supports multi-hop questions such as quote → purchase order → delivery note →
invoice → penalty notice. The matching evaluation set is
`data/golden/golden_fr_business_v1.jsonl`.

### Consistency guarantees

- The documents are generated by a script, and all arithmetic is computed and then
  checked independently. Line totals equal quantity × unit price. Net amount before tax
  (HT) equals gross minus discount plus delivery charge. VAT (TVA) is exactly 20 % of HT,
  rounded to the cent. Total with tax (TTC) equals HT plus TVA. The register totals match
  the invoices.
- Penalty amounts follow the formulas stated in the contract and in the terms of sale:
  1 % × HT × working days, and TTC × 12 % × days / 365.
- The SIREN and SIRET numbers follow the `999 000 xxx` pattern and are chosen to
  **fail** the Luhn check, so they cannot be valid identifiers. The postal codes
  (99xxx) do not exist. Phone numbers use the 01 99 00 xx xx range. E-mail addresses
  use `example.com` or `.test` domains. The IBAN is all zeros.
- The corpus contains deliberate conflicts that the ambiguous and adversarial questions
  depend on. The contract overrides the terms of sale on the carriage-paid threshold
  (2 000 € vs 3 000 € HT), on the delivery lead time (15 vs 20 working days) and on the
  deposit (none vs 30 %).

## Ingest into a separate collection

Keep this corpus out of the default `evalrag` collection so it does not skew
evaluations on `data/docs`. `scripts/ingest.py` takes `--path`. Pass `--no-meta` so
that the repository's `README.md`, `EvalRAG.md` and `LEARN.md` are not ingested
alongside the corpus. The collection name comes from the `QDRANT_COLLECTION` setting.

```bash
QDRANT_COLLECTION=evalrag_fr_business python scripts/ingest.py \
    --path data/demo_fr_business/docs --no-meta
```

Documents are named by their path relative to `--path`, so the stored names are the
bare filenames (`06_facture_FA-2026-0311.md`, ...). These are the same identifiers
that the golden set uses in `expected_sources` and `relevant_doc_ids`.

## Evaluate

Run every command with the same `QDRANT_COLLECTION`:

```bash
# Retrieval only (no LLM cost): hit rate, recall, MRR against expected_sources
QDRANT_COLLECTION=evalrag_fr_business python scripts/measure_retrieval.py \
    --dataset golden_fr_business_v1 --show-misses

# Full evaluation (retrieval + LLM judge)
QDRANT_COLLECTION=evalrag_fr_business python scripts/run_eval.py \
    --dataset golden_fr_business_v1 --strategy classic
QDRANT_COLLECTION=evalrag_fr_business python scripts/run_eval.py \
    --dataset golden_fr_business_v1 --all --no-judge
```

`QDRANT_COLLECTION` switches only the vector collection. Any other state the backend
keeps, such as the database, is shared with your usual setup.

## Regenerating

The generator is not part of the repository. If you edit a document by hand, recompute
its totals and update the affected `ideal_answer` and `evidence` entries in
`data/golden/golden_fr_business_v1.jsonl`. Every `evidence.quote` must stay a verbatim
substring of the named document.
